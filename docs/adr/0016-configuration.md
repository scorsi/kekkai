# ADR 0016 — Configuration

Status: Accepted — 2026-10-13

## Context

Every host is deployed through Nix; secrets come from sops as files. The author's convention (kajiba ADR 0019) is a TOML file generated by the module, with secrets referenced by path.

## Options considered

- CLI flags or environment variables: unreadable in a module, secrets leak into `ps` and logs.
- One TOML per binary generated by Nix, secrets as file paths.

## Decision

- One **TOML file per binary**, generated by the Nix module, passed as `--config <path>`, never hand-written. Schema defined by a single serde struct; the module options mirror it one to one. Safe defaults in code; the module writes only what differs.
- **No secret in the file**: only `private_key_file`. No environment variable except `RUST_LOG`.
- **Log level precedence**: `RUST_LOG`, when set, overrides `[log] level` from the file.
- `kekkai-node config check` (and the same subcommand on lighthouse and relay) validates a file; the `nixosTest` runs it against the module's output.
- **Reload**: in v0, a change restarts the service at `switch`. Sessions come back within a second and TCP survives. The core is designed for reload from day one (peer list is a replaceable value, 0004) and `SIGHUP` reload of the peer list is pulled into the real-network milestone (0026).
- Endpoints given as DNS names are resolved at start and again on keepalive failure.
- Shape of the node file (illustrative):

  ```toml
  [node]
  private_key_file = "/run/secrets/kekkai-key"
  listen_port = 4802
  addresses = ["10.x.y.z/32", "fdxx:…::z/128"]
  mtu = 1280                         # default and maximum in v0, lower it for a tight underlay (0009)

  [[peers]]
  name = "…"
  public_key = "base64…"
  addresses = ["…/32", "…/128"]
  endpoints = ["host:4802"]          # static, optional
  allow_inbound = ["tcp/22"]         # 0011

  [[lighthouses]]
  public_key = "…"
  endpoint = "host:4800"

  [[relays]]
  public_key = "…"
  endpoint = "host:4801"

  [log]
  level = "info"
  ```

  Lighthouse and relay have `[service]` (key file, port) and `[[peers]]` with `name` and `public_key` only.

## Consequences

- A unit test deserializes the complete example; a `nixosTest` proves the module's output is accepted by `config check`.
- The configuration file lives at a stable path (`/etc/kekkai/<role>.toml`) so that a reload trigger can target it (0026).

# ADR 0033 — The CLI in Rust

Status: Accepted — 2026-10-24

Amends 0002 (Go for the CLI), 0015 (Go client generated and committed, keygen vectors shared
by a Rust and a Go suite), 0023 (a new workspace member) and 0029 (new crates).

## Context

ADR 0002 chose Go for the `kekkai` CLI because the author's CLI conventions and generated gRPC
clients already existed in Go. Today the CLI is 178 hand-written Go lines (`main.go`, the key
helpers, the version constant), 102 test lines and 1304 generated lines, and it costs:

- a second implementation of the key code (`keygen`, `pubkey`) that only shared vectors keep
  in step with `kekkai-core` (0015);
- a second toolchain in the flake: `buildGoModule` with a `vendorHash`, the committed Go
  client and its `buf-generate` check, `go vet`/`go test`, `gofmt`, Go in the devShell and in
  `versions-identical` (0024);
- a second generated contract: every proto change is regenerated and committed for Go while
  Rust generates its own at build time.

Every command added later (reload, peer listing, the mutating RPCs 0015 prepares for) grows the
Go side and the cost of moving it. It is smallest now.

## Options considered

- **Keep Go.** No work now; the duplication above stays and grows with each command.
- **Rust, protojson through `pbjson`** (`pbjson-build` generates serde impls at build time):
  its own copy of the generated types with `pbjson-types` in place of `prost-types`, four new
  crates plus `chrono` and a second `base64`; an enum value the CLI does not know (a newer
  daemon, 0024) is a serialization **error**, where Go's protojson prints the number.
- **Rust, protojson through `prost-reflect`** (`serde` feature): the protojson mapping applied
  at run time to the message, described by the descriptor set `kekkai-control` already gets
  from protoc; unknown enum values print as numbers like Go; Timestamp and Duration through
  `prost-types`' formatting (0, 3, 6 or 9 fractional digits, as Go). Three new crates.
- **Rust, hand-written JSON** for the nine messages: no crate, but one more hand-written
  mirror of the contract to keep in step, which is what this ADR removes.

## Decision

- The CLI becomes a Rust binary of the workspace: `apps/cli/`, package and binary `kekkai`
  (built as `apps/cli-rs/`, package `kekkai-cli`, while the Go CLI still occupied the name). `keygen` and `pubkey` call `kekkai-core`'s `StaticKey` (the code the
  daemons load keys with, checked by the shared vectors); `status` is a tonic client over the
  Unix socket, generated by `kekkai-control` (which now also builds the client and exports
  its `FileDescriptorSet`); the reply is printed with `prost-reflect` and `serde_json`.
- **What does not change**, checked by the CLI's tests: the commands and arguments
  (`keygen [FILE]`, `pubkey`, `status --json [--socket PATH]`, `--version`), the usage text,
  `kekkai: <message>` on stderr with exit code 1 on any error and 0 otherwise, the default
  socket per platform (0015), the 5 s deadline, `keygen FILE` creating the file exclusively
  in mode 0400, `pubkey` reading at most 4096 bytes, the errors the nixosTests match
  (`permission denied` from the socket: system errors keep Go's lowercase wording), and the
  `status --json` output. Error texts no test covers may differ from Go's; no parity work is
  done for them.
- **`status --json` parity.** The output is protojson with the proto field names, enums as
  names, 64-bit integers as strings, Timestamp and Duration as strings, unset and default
  fields omitted, two-space indentation, fields in declaration order and a final newline:
  byte for byte what Go's `protojson.MarshalOptions{Multiline: true, UseProtoNames: true}`
  prints, except one point. Go's protojson inserts, per binary, either one or two spaces after
  each key (`internal/detrand`, seeded by a hash of the executable, so that callers do not
  depend on its whitespace); the shipped Go CLI therefore prints one or the other depending
  on its build. The Rust CLI prints one, the form Go prints with `detrand` disabled. This is
  insignificant JSON whitespace: every consumer parses the output (`jq`, Python's `json` in
  the nixosTests), none compares bytes.
- **Parity test.** The Go CLI's `apps/cli/status_test.go` (removed at step 3) built
  representative replies (empty, a node only, a node with peers on every path, every failure reason, every session state, an
  unknown enum value, 64-bit maxima, timestamps and durations at each precision and at their
  bounds, negative durations, strings needing escapes, a lighthouse, a relay) and committed,
  per reply, its wire encoding and what the Go CLI's `formatStatus` prints for it, with the
  `detrand` space removed, now under `apps/cli/testdata/status/`. The Rust test decodes each
  wire file as the client would and requires the golden **byte for byte**; it also requires
  every field and enum value of the contract to appear in a golden, so a proto change without
  a fixture fails. The Go test failed when its goldens were stale.
- **Fixtures after Go.** Once the Go CLI is removed (step 3) the committed goldens stay as they
  are, frozen, and the Rust test keeps checking every committed `.binpb`/`.json` pair. A later
  proto change adds its fixture by hand: the wire file encoded from a text-format reply
  (`protoc --encode`), the JSON written by hand and reviewed against protojson's JSON mapping.
  The Rust CLI has no mode that writes its own goldens: a golden printed by the code under test
  would check nothing.
- **Dependencies** (amends 0029), for `kekkai-cli` only:

  | Crate | Why |
  | --- | --- |
  | `prost-reflect` 0.14 (`serde`), with `serde-value` 0.7 and `ordered-float` 2 | protojson of the reply, as above |
  | `serde_json` 1 | the JSON writer; already in the lock (`kekkai-core`'s tests) |
  | `hyper-util` 0.1 (`tokio`), `tower` 0.4 (`util`) | the Unix-socket connector for tonic; already pulled by tonic |
  | `tokio` (`rt`, `net`, `time`), `tonic`, `prost`, `kekkai-control`, `kekkai-core` | as in 0029 |
  | `tokio-stream` (`net`), dev only | serves a reply on a Unix socket in a test |

  Argument parsing stays hand-written. Go: no new module (the Go test uses `durationpb` and
  `timestamppb` from `google.golang.org/protobuf`, already required).
- **Migration.**
  1. This ADR (proposed in 6149b74).
  2. The Rust CLI beside the Go one (a0c4792), with the parity test, built as the `kekkai-cli`
     package and covered by `cargo-test` and `cargo-clippy`. The `kekkai` package, the NixOS and
     darwin modules and the nixosTests keep the Go CLI.
  3. Once this ADR is accepted: the `kekkai` package becomes the Rust binary, moved to
     `apps/cli/` as the Cargo package `kekkai` (the `kekkai-cli` package is dropped); the Go
     module (`apps/cli`), its generated client, `buf.gen.yaml` (Go plugins only), `go.work`, the
     `go-test` and `buf-generate` checks, Go in the devShell, `gofmt` and the Go side of
     `versions-identical` are removed (it now also requires every binary to inherit the
     workspace version); every nixosTest runs once on the result. The goldens stay as frozen
     fixtures (above).
  4. ADRs 0002, 0015, 0022, 0023 and 0029 get a note pointing here.

## Consequences

- One language for everything kekkai ships, apart from glue scripts and the iOS shell (0002);
  one implementation of the key code; one generated contract, at build time (0023).
- `kekkai-control` compiles a client the daemons do not use; the CLI is built by crane like
  the daemons.
- `status --json` whitespace becomes stable across builds (always one space after a key).
- Until step 3 two `kekkai` binaries exist; only the Go one is installed by the modules.
